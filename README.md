# AnkiBook

Извлечение лексики из книг на английском и генерация карточек для интервального
повторения. Читаешь книгу где угодно, скармливаешь файл инструменту, получаешь
CSV для импорта в Noji или Anki.

Личный инструмент, один пользователь, всё хранится в файлах.

---

## Как это работает

```
книга.epub
    ↓  add        разбор, нормализация, токенизация, леммы
users/<имя>/books/<hash>.json
    ↓  rebuild    слияние всех книг в единый словарь
users/<имя>/dictionary.jsonl
    ↓  review     отбор кандидатов вручную, с контекстами из книги
статус proposed
    ↓  generate   карточки через LLM + валидация
users/<имя>/cards.jsonl
    ↓  export     CSV для импорта
users/<имя>/exports/2026-08-20-speak.csv
```

Две колоды:

- **speak** — активный словарь. Карточка-cloze: предложение с пропуском
  и русской подсказкой, ответ произносится вслух.
- **read** — пассивный словарь. Слово → перевод, только узнавание.

Слово попадает ровно в одну колоду. Основание: умение произнести включает
умение узнать, поэтому дублировать бессмысленно.

## Команды

### Основной цикл

| команда | что делает |
|---|---|
| `npm run add -- book.epub` | разбирает книгу, сохраняет факты и контексты в `users/<имя>/books/` |
| `npm run rebuild -- --apply` | пересобирает словарь из всех книг |
| `npm run review` | показывает кандидатов, ты выбираешь колоду |
| `npm run generate -- --limit 30` | генерирует карточки через LLM |
| `npm run export` | пишет CSV в `users/<имя>/exports/` |

```bash
npm run add -- samples/book.epub
npm run rebuild -- --apply
npm run review
npm run generate -- --limit 30
npm run export
```

**`add`** — форматы: `.txt`, `.epub`, `.docx`, `.rtf`, `.odt`, `.md`, `.html`,
`.pdf`. Хэш файла защищает от повторного добавления: одна книга дважды
удвоила бы счётчики.

**`rebuild`** — без `--apply` показывает diff и пишет `dictionary.next.jsonl`,
основной словарь не трогая. Это и есть отмена: посмотрел, что изменится, —
применил или нет. Отменить добавление книги = удалить её файл из `users/<имя>/books/`
и пересобрать.

**`review`** — по каждому слову показывает частотность, число вхождений,
контексты из книги и предложенную колоду.

| клавиша | действие |
|---|---|
| `Enter` | принять предложенное |
| `s` | в колоду speak |
| `r` | в колоду read |
| `k` | знаю это слово |
| `x` | не нужно |
| `b` | шаг назад |
| `q` | выход |

Решение пишется в словарь после каждого нажатия — выйти можно в любой момент,
ничего не потеряется.

**`generate`** — берёт слова со статусом `proposed`, для которых карточек ещё
нет. Можно гонять частями: уже сгенерированное пропускается. Колоды чередуются
пропорционально, чтобы read-слова не оставались за лимитом.

**`export`** — берёт карточки без замечаний валидатора, пишет по файлу на
колоду, ведёт журнал `users/<имя>/exports.jsonl`. Карточки с замечаниями пропускает:
исправить их после импорта в Noji будет нельзя.

### Служебные

| команда | что делает |
|---|---|
| `npm run tokens -- "текст"` | токенизация строки: форма, лемма, POS, позиция |
| `npm run ingest -- book.epub out.txt` | только нормализованный текст, без словаря |
| `npm run typecheck` | проверка типов |
| `npm run clean` | удалить все данные пользователя (спросит подтверждение) |

`tokens` полезен, чтобы быстро проверить разбор конкретной фразы:

```
$ npm run tokens -- "He saw the fish and left the harbour."
  ПОЗ  ФОРМА         ЛЕММА         POS
    0  He            he            PRON
    3  saw           see           VERB ←
   20  left          leave         VERB ←
   29  harbour       harbor        NOUN ←
```

Стрелка помечает, где лемма отличается от формы.

### Флаги

```bash
npm run review   -- --speak 20 --read 10
npm run generate -- --limit 50
npm run rebuild  -- --apply
```

Умолчания — в `src/config/tuning.ts`.

## Статусы слова

Не очевидно, но важно: **статус меняют только `review` и `export`.**

| команда | переход |
|---|---|
| `review` | `new` → `proposed` |
| `generate` | не трогает, пишет только `cards.jsonl` |
| `export` | `proposed` → `accepted` |

`accepted` ставится в момент экспорта, а не выбора. Иначе сбой на генерации
оставил бы слово помеченным как добавленное, а карточки бы не появилось —
и предложено оно больше никогда не было бы.

Строка с решением переживает пересборку, даже если источников не осталось:
слово могло уехать в Noji, откуда карточку не забрать. Строки без решений
и без источников выбрасываются — держать их значит копить мусор.

Тупиковые статусы: `known` (знаю) и `rejected` (не нужно). Различаются
намеренно: `known` — информация об уровне, годится для калибровки порога;
`rejected` — просто отказ, на уровень не влияет.

## Структура

```
src/
  cli/       команды
  config/    tuning.ts (значения с комментариями) + index.ts (аргументы)
  llm/       порт к модели, клиент, промпты
  text/      файл → текст → токены → леммы, границы служебного текста
  library/   словарь, частотность, скоринг, хранение
  cards/     генерация и валидация карточек
prompts/     тексты промптов в markdown
data/        частотная таблица (97 781 слово)
tools/       генератор таблицы, Python, вручную
users/       данные пользователей, папка на каждого, в .gitignore
```

`cli/` содержит только адаптеры: аргументы, вывод, файлы. Логика — без
обращений к `process` и `console`.

Настройки и их обоснование: [CONFIG.md](CONFIG.md).

## Данные пользователя

```
users/<имя>/
  books/<hash>.json           факты книги: леммы, счётчики, позиции
  books/<hash>.txt            нормализованный текст
  books/<hash>.contexts.json  примеры предложений
  books/<hash>.excluded.json  слова этой книги, которые ты не взял
  dictionary.jsonl            словарь: счётчики + статусы
  cards.jsonl                 сгенерированные карточки
  exports.jsonl               журнал выгрузок
  exports/*.csv               файлы для импорта
  session.json                положение в мастере веб-версии
  profile.json                knownZipf и прочее про пользователя
```

**Пользователь — это папка.** Список пользователей не хранится нигде: это
то, что лежит в `users/`. Завёл папку руками — она появилась в приложении,
удалил — исчезла, и разойтись с действительностью список не может.

Веб-версия присылает выбранного пользователя в заголовке каждого запроса,
командам он задаётся флагом:

```bash
npm run add -- book.epub --user Вера
npm run rebuild -- --apply --user Вера
```

Без флага — `Default`.

Всё в `.gitignore`, кроме `.gitkeep`. Словарь — производное состояние:
источник истины это `books/` плюс твои решения, остальное пересчитывается.

**`excluded.json` — список отказов, а не список включённых.** Нет файла —
книга идёт в словарь целиком, поэтому `rebuild` работает как работал.
Отказ относится к книге, а не к слову навсегда: та же лемма из другой книги
войдёт как новая. Лежит отдельно от `<hash>.json`, потому что тот файл
описывает текст — леммы, счётчики, позиции, — и всё это выводится из книги.
Решение человека фактом о книге не является.

Отказавшись, слово теряешь: в словаре не остаётся ни строки, ни статуса.
Это и есть цель — словарь должно быть можно прочитать глазами. Передумать
можно, вернувшись на шаг отбора: чего нет в словаре, то снова в списке.

## Ограничения

**Карточку из Noji нельзя ни исправить, ни удалить — только добавить.**
Отсюда четыре обязательных проверки перед экспортом: утечка ответа в подсказку,
русский когнат ответа, неоднозначность контекста, соответствие буквы пропуска.
Не прошедшие карточки не выгружаются.

**Только английский.** Частотная таблица и модель лемматизации английские.

**Фразовые глаголы не извлекаются.** У winkNLP нет синтаксического разбора
зависимостей, а частица фразового глагола размечается как обычный предлог —
`picked up` и `walked in` неразличимы. Нужен курируемый словарь фразовых
глаголов, его пока нет.

**История чтения оживает со второй книги.** `bookCount` и правило «слово
из третьей книги» на одной книге проверить нечем.
